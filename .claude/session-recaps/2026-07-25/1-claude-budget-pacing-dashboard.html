Non-obvious

Gotchas9

›

/usage can't be automated

Tested: claude -p "/usage" resolves in 8ms with zero tokens but returns only a generic sentence. The numbers are TUI-rendered and never serialize. /status is unavailable headless.

Fable draws from the same budget

Not a separate pool — it counts toward the weekly limit AND is capped at 50% of it. Fable usage moves both meters.

Never override a documented number with an inferred one

I fixed Fable's weight at its API price ratio and solved for the share, contradicting Anthropic's published 50%. Backwards — solve for the guess, trust the document. Fable actually costs ~6.7× Opus, not 2×.

A calibration that won't stay put is a wrong model

The "share" needed re-deriving every reading. That wasn't noise — it was one parameter absorbing an error in another.

Unknown keys returning 0 hide bugs

A stale pool name ('standard') silently produced zero twice: once making the 5h block permanently "none open", once degrading a calibration solve while still saving a bogus limit.

Never show dollars

On a subscription there is no dollar meter. API prices are used only as relative weights; every displayed figure is a share of the weekly allowance.

Rolling windows, not calendar weeks

A calendar-week maximum ignores the in-progress week, letting a heavy current week exceed its own inferred limit and pin remaining budget to zero.

A mid-week reset spans 8 days

Wed 15:45 → Wed 15:45 touches eight calendar days, two partial. Each is weighted by its overlap; the two fragments sum to exactly one day.

~/Desktop is TCC-protected

Files written there are unreadable to the preview runner and will be to launchd too — EPERM on a file just created. Grant FDA or relocate.
